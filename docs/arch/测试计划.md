# ROSbot Lite 测试计划

## 1. 目标

本计划用于验证 ROSbot Lite 数字板固件在当前硬件上的可用性、稳定性和与上位机 ROS 2 系统的联通性。

本次测试范围依据当前代码实现与 Husarion 公开资料确定，重点覆盖以下能力：

- 串口 micro-ROS 通信
- 4 路电机驱动与编码器反馈
- BNO055 IMU 数据发布
- 电池电压采集
- 按键、状态灯与灯带控制
- 电机电流与堵转状态上报
- 板级上电、任务调度与异常状态指示

不纳入本次测试范围的内容：

- 以太网 micro-ROS 通信
- ROSbot XL 专有配置项
- ROSbot 旧版 ranges 传感器链路

## 2. 依据

### 2.1 本地代码实现

- 当前 Lite 主流程在 src/rosbot_lite/main.cpp 中初始化电池、编码器、NTC 风扇、BNO055、状态灯、灯带、电机和串口 micro-ROS 通道。
- 当前 Lite 话题与服务定义在 src/rosbot_lite/ros.cpp 中，实际包含：battery、buttons、_imu/data、_motors/cmd、_motors/feedback、leds、led_strip、_mcu_id，以及电机电流/堵转发布器。
- 当前 Lite 周期任务定义在 src/rosbot_lite/rtos.cpp 中，包含 Encoder、HwMonitor、Imu、LedStrip、MotorControl、Shutdown、uRos、uRosPing 等任务。
- Lite 引脚和硬件映射定义在 include/rosbot_lite/config.hpp 中。

### 2.2 Husarion 公开资料

- husarion/rosbot-firmware README 说明当前固件工作分为连接选择、预通信和 micro-ROS 主通信三个阶段，并给出串口 agent 启动方式。
- husarion/rosbot_ros README 说明 ROSbot 实机 bringup 依赖 firmware 版本兼容，并通过 rosbot_bringup 启动实际机器人。
- husarion/rosbot_xl_firmware README 说明 Husarion 官方推荐通过 micro-XRCE 或 micro-ROS agent 建立与数字板的通信。

## 4. 测试前提

### 4.1 硬件前提

- ROSbot Lite 数字板已正确上电。
- 电机、电池、IMU、编码器、灯带、电源板连接完成。
- 主控/上位机与板卡串口链路已接好。
- 如需重新烧录，需保证 ST-Link 或其他调试器连接正常。

### 4.2 软件前提

- 固件编译环境可用。
- 已有可用的 ROS 2 环境和 micro_ros_agent。
- 如果要做实机 bringup，需准备与 firmware 版本兼容的 rosbot_ros。

### 4.3 推荐上位机命令

串口 agent 启动命令：

```bash
ros2 run micro_ros_agent micro_ros_agent serial --dev <serial_port> --baud <baud_rate>
```

ROSbot bringup 参考命令：

```bash
ros2 launch rosbot_bringup rosbot.yaml
```

注：Lite 当前实现明确使用串口 transport，不使用 Ethernet。

## 5. 测试分阶段计划

## 5.1 阶段 A：静态与环境检查

### A-1 固件构建验证

- 目的：确认当前代码可稳定构建。
- 步骤：执行 platformio run -e rosbot_lite。
- 预期结果：构建成功，生成 firmware.elf。
- 判定：通过/失败。

### A-2 下载链路验证

- 目的：确认调试器链路可用于重新下载固件。
- 步骤：执行 platformio run -e rosbot_lite --target upload。
- 预期结果：OpenOCD 能连接调试器并完成烧录。
- 判定：通过/失败。

### A-3 上位机串口识别

- 目的：确认板卡串口能被宿主机识别。
- 步骤：枚举串口设备并记录端口号。
- 预期结果：出现对应串口设备。
- 判定：通过/失败。

## 5.2 阶段 B：板级基础功能单元测试

### B-1 状态灯自检

- 步骤：板卡上电，观察红绿灯默认状态和离线状态闪烁逻辑。
- 预期结果：默认红灯进入待机/离线指示；切换诊断模式时绿灯可被点亮。

### B-2 按键输入测试

- 步骤：短按两个用户按键，观察 buttons 话题数值变化。
- 预期结果：按键位图变化稳定，无抖动异常。

### B-3 EEPROM/板卡版本读取测试

- 步骤：上电启动，确认系统可正常完成 board_revision.init。
- 预期结果：不会因 EEPROM 访问失败卡死启动流程。

### B-4 电池 ADC 测试

- 步骤：测量电池实际电压，同时读取 battery 话题。
- 预期结果：采样值与万用表误差在可接受范围内。

### B-5 IMU 测试

- 步骤：静止读取 _imu/data，然后缓慢旋转车体。
- 预期结果：姿态与角速度变化方向正确，静止噪声可接受。

### B-6 灯带测试

- 步骤：向 led_strip 发布 rgb8 图像消息。
- 预期结果：18 颗灯珠正确响应；无消息时进入空闲动画。

### B-7 风扇测试

- 步骤：读取 NTC 温度并观察风扇 PWM 输出变化。
- 预期结果：温度升高后占空比增大。

## 5.3 阶段 C：运动系统单元测试

### C-1 编码器方向测试

- 步骤：断电状态手动转动各轮，读取 _motors/feedback。
- 预期结果：四个轮子的 joint name、方向和速度符号正确。

### C-2 单轮点动测试

- 步骤：以低速逐个发布四轮速度命令。
- 预期结果：每个轮子独立响应，方向与配置一致，无异常啸叫。

### C-3 四轮联动测试

- 步骤：发布前进、后退、原地旋转和平移组合速度。
- 预期结果：车体运动方向正确，四轮速度反馈一致性良好。

### C-4 电流采样测试

- 步骤：空载和轻载下运行电机，记录 motor current 话题。
- 预期结果：电流变化合理，左右/前后轮差异在机械允许范围内。

### C-5 堵转保护测试

- 步骤：短时间限制轮子运动，观察 stall 话题与系统行为。
- 预期结果：检测到高电流低转速条件后触发堵转上报。

## 5.4 阶段 D：micro-ROS 通信与系统联调

### D-1 Agent 连接测试

- 步骤：启动 micro_ros_agent，并连接 Lite 串口。
- 预期结果：g_ros_node 从 WAITING 进入 CONNECTED，相关 topic 开始发布。

### D-2 Topic 发布完整性测试

- 步骤：依次查看 battery、buttons、_imu/data、_motors/feedback 以及电流/堵转话题。
- 预期结果：所有应发布 topic 均存在且刷新率符合预期。

### D-3 Service 测试

- 步骤：调用 _mcu_id 服务。
- 预期结果：返回 12 字节 UID 的十六进制字符串。

### D-4 控制闭环测试

- 步骤：持续发送 _motors/cmd，观察反馈速度跟踪情况。
- 预期结果：四轮速度能跟随目标变化，稳态误差在可接受范围内。

## 5.5 阶段 E：整机场景测试

### E-1 空载运行 10 分钟

- 目标：验证温升、任务调度、通信稳定性。

### E-2 低速直行与原地旋转

- 目标：验证底盘运动学方向与轮组一致性。

### E-3 带载短时运行

- 目标：验证电流采样、温升与堵转检测阈值是否合理。

### E-4 重连恢复测试

- 步骤：拔掉 agent 或串口，随后恢复连接。
- 预期结果：节点可从 DISCONNECTED 回到 CONNECTED。

## 6. 建议的执行顺序

1. 先做阶段 A，确认构建、下载链路和串口识别。
2. 再做阶段 B，确认传感器和板级 IO 正常。
3. 然后执行阶段 C，先单轮再整车，避免一次性联动造成机械风险。
4. 最后做阶段 D 和 E，验证与 ROS 2 系统的整合。

## 8. 已执行结果

### 8.1 已完成

- A-1 固件构建验证：通过。
- 结果：rosbot_lite 环境编译成功，RAM 占用约 51.5%，Flash 占用约 18.5%。

### 8.2 当前阻塞

- A-2 下载链路验证：失败。
- 现象：PlatformIO 调用 OpenOCD 后报错 open failed，upload 终止。
- 判断：当前不是编译问题，而是调试器连接链路问题。结合宿主机设备枚举结果，Windows 当前未检测到在线 ST-Link，能够直接解释 upload 使用 stlink 协议时报错 open failed。优先检查 ST-Link 是否连接、驱动是否正常、目标板是否上电，以及 SWD 线序是否正确。

### 8.3 新增执行结果

- A-3 上位机串口识别：通过。
- 结果：PlatformIO 当前可见两个串口设备 COM21 和 COM25，说明宿主机已枚举到串口链路，但尚未进一步确认哪一个对应 Lite 主通信串口。
- D-1 Agent 连接测试：暂未执行。
- 原因：当前 Windows PowerShell 环境中 ros2 命令不可用，因此不具备直接启动 micro_ros_agent 的条件。

## 9. 下一步执行建议

1. 先修复 ST-Link/SWD 连接问题，确保 A-2 通过。
2. 确认宿主机已识别 Lite 的主通信串口。
3. 启动 micro_ros_agent，优先完成 D-1、D-2、D-3。
4. 在车辆离地条件下执行 C-1 到 C-4，最后再做整车运动测试。
