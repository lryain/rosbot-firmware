# ROSbot XL 电源板逆向工程与设计文档

> 本文档基于 `lib/power_board/power_board.cpp` 和 `power_board.hpp` 源码逆向分析，旨在为 ROSbot PRO 的电源板设计提供完整参考。

---

## 1. 电源板概述

ROSbot XL 的硬件由两块 PCB 组组成：
- **数字板（Digital Board）**：STM32F407LGT6 主控，负责电机控制、传感器读取、ROS 通信
- **电源板（Power Board）**：独立 MCU，负责电池管理、电源分配、关机控制

两板之间通过 **UART** 通信，电源板作为从设备，响应数字板的查询请求。

### 1.1 电源板的核心职责

| 功能 | 说明 |
|------|------|
| 电池状态监测 | 电压、温度、充放电电流、健康状态、技术类型 |
| 板卡信息上报 | 固件版本、硬件版本 |
| USB-C PD 充电管理 | 12-20V USB-C PD 输入 |
| SBC 供电管理 | 5V/12V/19V 可配置输出（通过 DIP 开关） |
| 关机协调 | 检测关机按钮 → 通知 SBC → 等待确认 → 断电 |

## 2. UART 通信协议详解

### 2.1 物理层

| 参数 | 值 |
|------|------|
| 接口 | UART（异步串口） |
| 波特率 | 38400 bps |
| 数据位 | 8 bit |
| 校验 | 无 |
| 停止位 | 1 bit |
| 数字板引脚 | TX=PD5, RX=PD6 (USART2) |
| 超时 | 100ms |

### 2.2 帧格式

协议采用 **ASCII 十六进制编码** 的帧格式：

```
<CC SS AA...AA CS>
```

| 字段 | 长度 | 说明 |
|------|------|------|
| `<` | 1 字节 | 帧起始标记 (0x3C) |
| CC | 2 字符 | 命令字节的十六进制表示 |
| SS | 2 字符 | 参数长度的十六进制表示 |
| AA...AA | SS×2 字符 | 参数数据，每字节用2个十六进制字符表示 |
| CS | 2 字符 | 校验和的十六进制表示 |
| `>` | 1 字节 | 帧结束标记 (0x3E) |

### 2.3 校验和算法

```
checksum = CMD ^ ARG_SIZE ^ ARG[0] ^ ARG[1] ^ ... ^ ARG[N-1]
```

采用 **XOR** 累积校验，覆盖命令字节、参数长度、所有参数数据。

### 2.4 十六进制编码示例

原始字节 `0xAB` 编码为 ASCII 字符 `'a'` `'b'`（小写十六进制）。

发送帧编码流程：
```c
// 1. 写入 '<'
// 2. CMD 字节 → 2个十六进制 ASCII 字符
// 3. ARG_SIZE 字节 → 2个十六进制 ASCII 字符
// 4. 每个 ARG[i] → 2个十六进制 ASCII 字符
// 5. CHECKSUM 字节 → 2个十六进制 ASCII 字符
// 6. 写入 '>'
```

接收帧解码流程：
```c
// 1. 扫描 '<' 起始标记
// 2. 解码 CMD（2字符 → 1字节）
// 3. 解码 ARG_SIZE（2字符 → 1字节）
// 4. 检查剩余缓冲区是否足够：需要 8 + ARG_SIZE×2 字节
// 5. 逐个解码 ARG[i]，XOR 累积校验
// 6. 解码收到的 CHECKSUM，与计算值比对
```

## 3. 命令定义

### 3.1 CMD 0x01 — 板卡信息查询 (CMD_BOARD_INFO)

**请求方向**：数字板 → 电源板

**请求帧**：
```
参数长度: 1
参数内容: [0x00]  (请求标志，固定为0)
```

**响应帧**：
```
参数长度: 25 (BOARD_INFO_ARG_LEN)
```

**响应参数布局**：

| 偏移 | 长度 | 类型 | 字段 | 说明 |
|------|------|------|------|------|
| 0 | 1 | uint8 | 保留 | 未使用 |
| 1-11 | 11 | char[11] | firmware_version | 固件版本字符串 |
| 12 | 1 | uint8 | 保留 | 分隔符 |
| 13-24 | 12 | char[12] | board_version | 硬件版本字符串 |

**使用场景**：数字板在启动时查询一次板卡信息，如果未获取到有效信息会持续重试。

### 3.2 CMD 0x02 — 电池状态查询 (CMD_BATTERY_STATE)

**请求方向**：数字板 → 电源板

**请求帧**：
```
参数长度: 18 (BATTERY_STATE_ARG_LEN)
参数内容: 全零 [0x00 × 18]
```

**响应帧**：
```
参数长度: 18 (BATTERY_STATE_ARG_LEN)
```

**响应参数布局**：

| 偏移 | 长度 | 类型 | 字段 | 单位/说明 |
|------|------|------|------|-----------|
| 0 | 1 | uint8 | 保留 | 未使用 |
| 1-2 | 2 | uint16 BE | voltage | ×0.001V (毫伏精度) |
| 3-4 | 2 | int16 BE | temperature | °C (范围 -100 ~ 200，超出为 NAN) |
| 5-6 | 2 | uint16 BE | discharge_current | ×0.001A (毫安精度) |
| 7-8 | 2 | uint16 BE | charge_current | ×0.001A (毫安精度) |
| 9-10 | 2 | uint8[2] | 保留 | 未使用 |
| 11-12 | 2 | uint16 BE | design_capacity | ×0.001Ah (毫安时精度) |
| 13 | 1 | uint8 | 保留 | 未使用 |
| 14 | 1 | uint8 | status | 电池状态码 |
| 15 | 1 | uint8 | health | 电池健康码 |
| 16 | 1 | uint8 | technology | 电池化学类型 |
| 17 | 1 | uint8 | present | 电池是否在位 (0/1) |

**注意**：
- 字节序为 **大端序 (Big-Endian)**
- 电流计算：`current = charge_current - discharge_current`
- 电量百分比由数字板根据电压线性估算：`percentage = (voltage - v_min) / (v_max - v_min)`
- 原始电池参数：v_min=9.6V, v_max=12.6V（3S 锂电池）

**数据更新频率**：1Hz（在 `hwMonitorTask` 中每 1000ms 请求一次）

## 4. 关机协调机制

### 4.1 引脚定义

| 引脚 | 方向 | 功能 |
|------|------|------|
| PD4 (PB_SHD_DETECT) | INPUT_PULLUP | 检测电源板关机信号（高电平触发） |
| PD7 (PB_SHD_CONFIRM) | OUTPUT | 确认关机完成（拉高确认） |

### 4.2 关机流程

```
电源板                      数字板                       SBC (RPi)
  │                           │                            │
  │ ── PD4 = HIGH ──────────▶ │                            │
  │    (关机按钮被按下)         │                            │
  │                           │ ─── HTTP GET /shutdown ──▶ │
  │                           │     (192.168.77.2:3000)    │
  │                           │                            │ ── 开始关机 ──
  │                           │◀──── (TCP 连接关闭) ────── │
  │                           │                            │
  │                           │ ── delay 5000ms ────────── │ (等待SBC完成)
  │                           │                            │
  │ ◀── PD7 = HIGH ───────── │                            │
  │    (确认可以断电)           │                            │
  │                           │ ── vTaskSuspend ──────────  (MCU停止)
  │ ── 断开电源 ──────────────                              │
```

### 4.3 关键设计参数

- 关机等待超时：5000ms (`SHUTDOWN_WAIT_MS`)
- SBC 通知方式：HTTP GET 请求到 `AGENT_IP:3000/shutdown`
- 关机检测轮询频率：3Hz（`shutdownTask` 周期）

## 6. ROSbot PRO 电源板设计方案

### 6.1 第一版方案：ADC 直接测量（无电源板）

由于 ROSbot PRO 第一版不包含电源板，采用 ROSbot 的 ADC 方式直接测量电池电压：

```c
// 参考 ROSbot 的 BatteryAdcConfig
BatteryAdcConfig battery_adc_config = {
    .adc_pin = PA5,        // 或其他可用 ADC 引脚
    .v_ref = 3.3f,         // MCU 参考电压
    .v_min = 9.6f,         // 3S 锂电截止电压
    .v_max = 12.6f,        // 3S 锂电满电电压
    .divider = 6.6f,       // (56K + 10K) / 10K = 6.6
    .correction = 0.986f,  // 校准系数
    .adc_resolution_scale = 1.0f / 1023,  // 10-bit ADC
};
```

**电压分压器设计**：
```
电池+ ──┬── R1 (56kΩ) ──┬── R2 (10kΩ) ──┬── GND
                         │
                      ADC Pin (PA5)
                    (Vmax = 12.6V × 10/66 ≈ 1.909V)
```

**限制**：
- 仅能测量电压，无温度/电流数据
- 电量百分比基于电压线性估算
- 不支持关机协调
- 不支持充电管理

### 6.2 第二版方案：完整电源板

#### 6.2.1 推荐 MCU

| 选项 | MCU | 优势 | 劣势 |
|------|-----|------|------|
| A+ | RP2530 | | 有开源现成的固件，树莓派生态 |
| A | STM32G030 | 成本低、生态好、与主板同系 | 需要外围电路 |
| B | STM32G070 | USB/CAN 支持 | 成本稍高 |
| C | ESP32-C3 | WiFi、OTA 升级 | 功耗较高 |

推荐选择 **STM32G030**，成本低且外设足够。

#### 6.2.2 推荐电池管理方案

**方案 A：智能燃料计 IC**
- IC: TI BQ40Z50 或 BQ34Z100-G1
- 优势：精确的库仑计量、完整的电池数据
- 电源板 MCU 通过 SMBus/I2C 读取数据

**方案 B：分立测量**
- 电压：分压器 + ADC
- 电流：INA219/INA226 电流传感器
- 温度：NTC 热敏电阻
- 优势：成本低、设计简单，与 ROSbot 的 NTC 方案一致

#### 6.2.3 通信协议建议

保持与 Husarion 协议兼容的 UART 帧格式，以便代码复用：

```
保持不变：
- 帧格式: <CC SS AA..AA CS>
- 波特率: 38400
- 校验算法: XOR
- 命令字: CMD_BOARD_INFO(0x01), CMD_BATTERY_STATE(0x02)

建议扩展：
- CMD 0x03: 充电状态 (USB-C PD 状态、充电电压/电流)
- CMD 0x04: 电源输出控制 (5V/12V 开关)
- CMD 0x05: 固件升级 (OTA bootloader)
```

## 7. 代码接口兼容性

### 7.1 BatteryInterface 抽象层

```cpp
class BatteryInterface {
 public:
  virtual void init() = 0;
  virtual void update() = 0;
  virtual const BatteryData getData() const;
  virtual const char* name() const = 0;
  virtual bool isLow(float thresh = 0.2, float hist = 0.02);
  virtual bool isCritical(float thresh = 0.05, float hist = 0.02);
};
```

当前已有两个实现：
- `BatteryAdc`: ADC 直接测量（ROSbot 使用）- 仅电压和百分比
- `PowerBoard`: UART 电源板通信（ROSbot XL 使用）- 完整电池数据

### 7.2 ROSbot PRO 兼容策略

```cpp
// 第一版：无电源板，使用 ADC
BatteryInterface* g_battery = new BatteryAdc(battery_adc_config);

// 第二版：有电源板，使用 UART
// BatteryInterface* g_battery = new PowerBoard(power_board_config);
```

通过 `BatteryInterface` 多态，上层代码（ROS publisher、RTOS task）完全无需修改。

## 9. 总结

| 版本 | 方案 | 代码修改量 | 硬件复杂度 |
|------|------|-----------|-----------|
| V1 (无电源板) | BatteryAdc + 分压器 | 极小 - 仅切换接口实现 | 低 - 2个电阻 |
| V2 (有电源板) | PowerBoard + UART | 零 - 完全兼容现有代码 | 高 - 独立 PCB |

ROSbot PRO 第一版建议使用 ADC 方案快速验证，第二版再设计完整电源板以获得充电管理和精确的电池监测能力。
