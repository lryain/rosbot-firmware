
# ROSbot Lite 固件上电运行流程详解

> 本文档基于源码深度分析，帮助你理解控制板上电后的完整行为，方便观察和调试。

---

## 一、上电后的完整执行流程（按时间顺序）

### 阶段1：硬件初始化（`boardPheripheralsInit()`）

上电后，MCU 首先执行板级外设初始化，此时**不会**有任何电机动作：

| 步骤 | 操作 | 可观察现象 |
|------|------|-----------|
| 1 | 音频功放使能（AUDIO_SHDN = PD15 → HIGH） | 无明显现象 |
| 2 | 用户按键初始化（PE14、PE15 上拉输入） | 无 |
| 3 | **红色LED点亮**（PE4 → HIGH） | 🔴 **红灯亮起** |
| 4 | 5V外设电源使能（PE2 → HIGH） | 外设供电开启 |
| 5 | 电源板关机握手引脚初始化（PD4 输入上拉、PD7 输出低） | 无 |
| 6 | I2C2 总线初始化（PB10/PB11，400kHz） | 无 |
| 7 | 延时50ms等待稳定 | — |

> ✅ **检查点**：上电后红灯应立即亮起。如果没亮，说明基本硬件初始化就失败了。

---

### 阶段2：通信通道选择（`g_comm_mgr.init()` + `selectTransport()`）

固件需要决定用哪个串口和 SBC（上位机）通信：

| 步骤 | 操作 | 可观察现象 |
|------|------|-----------|
| 1 | 初始化两个串口：SBC串口（USART1, PA9/PA10, 921600bps）和诊断串口（USART3, PD8/PD9, 921600bps） | 无 |
| 2 | **等待2秒**，检测用户按钮1（PE14）是否被按下 | ⏳ **上电后有2秒的选择窗口** |
| 3 | 如果按钮1按下（低电平）→ 使用诊断串口作为ROS通信通道，绿色LED亮起确认 | 🟢 绿灯亮 = 诊断模式 |
| 4 | 如果2秒超时无按键 → 使用SBC串口作为ROS通信通道，诊断串口留给调试 | 正常模式 |

> ✅ **检查点**：上电后2秒内按住按钮1（PE14），绿灯亮起表示进入了诊断模式。

---

### 阶段3：命名空间协商（`configureNamespace()`）

通过选定的串口与SBC进行命名空间握手：

| 步骤 | 操作 | 可观察现象 |
|------|------|-----------|
| 1 | 通过串口发送 `FW: 0.0.0
`（固件版本号） | 串口有输出 |
| 2 | 每250ms重发一次 `FW: 0.0.0
` | — |
| 3 | 等待SBC回复 `NS:xxx
` 格式的命名空间 | 最多等1秒 |
| 4 | 收到后回复 `ACK` | 握手完成 |
| 5 | 如果超时未收到 → 使用默认空命名空间 | 静默继续 |

> ⚠️ **注意**：如果没有连接SBC，此步骤会在1秒后超时继续，**不会卡住**。

---

### 阶段4：外设初始化（各 `init()` 调用）

依次初始化所有外设，**这是电机可能动作的关键阶段**：

| 步骤 | 操作 | 可观察现象 |
|------|------|-----------|
| 1 | EEPROM读取板子版本号 | 无 |
| 2 | 电池ADC初始化（PA5） | 无 |
| 3 | **4个编码器初始化**（TIM2/TIM3/TIM4/TIM1 硬件定时器编码器模式） | 无 |
| 4 | NTC温度传感器初始化（PB1） | 无 |
| 5 | 风扇控制器初始化（PB0, TIM8 CH2N, 25kHz PWM） | 风扇可能开始转 |
| 6 | IMU（BNO055）初始化（I2C地址0x29） | 无 |
| 7 | LED指示器初始化（红色PE4，初始高电平=亮） | 🔴 红灯仍亮 |
| 8 | LED灯带初始化（SPI, 18颗LED，初始红色 0x0F,0x00,0x00） | 🔴 **灯带亮红色** |
| 9 | **⚠️ 电机数组初始化（`g_motors.init()`）** | **见下方详细分析** |

#### 电机初始化详细流程（`g_motors.init()`）

这是**电机会动作的关键环节**：

```
1. 创建互斥锁
2. 配置驱动器引脚：
   - 左侧驱动器：nSLEEP=PD10(输出), nFAULT=PE0(输入上拉)
   - 右侧驱动器：nSLEEP=PD11(输出), nFAULT=PE1(输入上拉)
3. disableDrivers() → nSLEEP全部拉低 → 驱动芯片休眠
4. 逐个初始化4个电机（motor_fl/fr/rl/rr → init()）：
   - 配置IN1/IN2引脚的PWM定时器
   - 设置PWM频率20kHz，初始占空比0%
   - ⚠️ setMode(COAST) → IN1=0, IN2=0 → 电机滑行（不通电）
5. enableDrivers() → nSLEEP全部拉高 → 驱动芯片唤醒
   - ⚠️ 唤醒后延时100us等待DRV8874稳定
```

> **🔍 电机"自检"现象分析**：
>
> 代码中**没有显式的自检程序**（没有让电机正转反转的代码）。
> 但上电时电机可能会短暂抖动，原因可能是：
>
> 1. **DRV8874唤醒瞬态**：`enableDrivers()` 将 nSLEEP 拉高时，DRV8874从休眠
>    唤醒，在稳定之前输出端可能有短暂毛刺，导致电机轻微抖动。
> 2. **PWM定时器初始化**：`setPWM()` 配置定时器时，在完全稳定前可能有瞬态
>    输出脉冲。
> 3. **PID积分器漂移**：电机初始化后target_velocity=0，但PID控制器的积分项
>    在最初的几次update()中可能因为编码器噪声产生微小输出。
>
> **如果电机持续转动**，那不是自检，而是异常！请检查：
> - 编码器接线是否正确（接错会导致PID误判速度）
> - 电机IN1/IN2引脚是否焊接短路
> - DRV8874的nFAULT引脚是否为高电平（低=故障）

---

### 阶段5：micro-ROS 传输初始化

| 步骤 | 操作 | 可观察现象 |
|------|------|-----------|
| 1 | 配置micro-ROS串口传输层（XRCE framing启用） | 无 |
| 2 | 设置诊断串口用于调试输出 | 无 |

---

### 阶段6：FreeRTOS 启动（`createQueues()` + `createTasks()` + `vTaskStartScheduler()`）

创建消息队列和所有任务，然后启动调度器。**从这一刻起，程序进入多任务并行运行**。

#### 创建的队列

| 队列名 | 用途 | 容量 |
|--------|------|------|
| battery_queue | 电池数据 | 1 |
| imu_queue | IMU数据 | 1 |
| joint_state_queue | 编码器/关节状态 | 1 |
| led_strip_queue | LED灯带帧数据 | 1 |
| motor_current_queue | 电机电流 | 1 |
| motor_stall_queue | 电机堵转状态 | 1 |

#### 创建的任务（按优先级从高到低）

| 任务名 | 优先级 | 频率 | 栈大小 | 功能 |
|--------|--------|------|--------|------|
| MotorControl | 5 (CONTROL) | 200Hz | XXS | 电机PID更新+电流/堵转检测 |
| Encoder | 5 (CONTROL) | 500Hz | XXS | 编码器读取+电流填充 |
| uRos | 4 (COMM) | 1000Hz | L | ROS2 executor spin |
| Imu | 3 (SENSORS) | 100Hz | M | IMU数据更新 |
| HwMonitor | 2 (OBSERV) | 10Hz | S | LED指示+电池+风扇+温度 |
| LedStrip | 2 (OBSERV) | 25Hz | S | LED灯带动画 |
| Shutdown | 2 (OBSERV) | 3Hz | M | 电源板关机握手 |
| uRosPing | 1 (BLOCK) | 2Hz | XL | ROS Agent连接状态机 |

## 二、运行时的关键行为

### 2.1 ROS连接状态机（`uRosPingTask` → `g_ros_node.loop()`）

这是最核心的状态机，决定了整个控制板的行为：

```
┌──────────┐  ping成功   ┌─────────────────┐  createEntities成功  ┌───────────┐
│ WAITING  │───────────→│ AGENT_AVAILABLE │────────────────────→│ CONNECTED │
│ (等待中)  │            │  (Agent可用)     │                     │ (已连接)   │
└──────────┘            └─────────────────┘                      └───────────┘
     ↑                                                       │
     │                    ping失败                            │
     └───────────────────────────────────────────────────────┘
                          DISCONNECTED
                          (断开连接 → 销毁实体 → 回到WAITING)
```

| 状态 | 含义 | LED表现 | 电机行为 |
|------|------|---------|---------|
| **WAITING** | 等待ROS Agent（micro-ROS Agent运行在SBC上） | 🔴 红灯常亮 | ⚠️ 看门狗未激活，电机PID运行但target=0 |
| **AGENT_AVAILABLE** | 检测到Agent，正在创建ROS实体 | 🔴 红灯常亮 | 同上 |
| **CONNECTED** | ROS2通信正常 | ⚫ 红灯灭 | ✅ 正常接收速度指令 |
| **DISCONNECTED** | 通信丢失，清理实体 | 🔴 红灯常亮 | ⚠️ 看门狗超时后电机制动 |

### 2.2 电机看门狗机制（重要！）

```
电机看门狗超时 = 500ms

当SBC发送速度指令 → motorsCmdCallback() → setVelocities() → feedWatchdog()
                                                                                  ↓
                                                                     重置看门狗计时器

如果500ms内没有新指令:
  isWatchdogExpired() = true
  → motorControlTask中 update(dt, !isWatchdogExpired())
  → move = false
  → 每个电机执行 brake() → IN1=HIGH, IN2=HIGH → 主动制动
```

> **🔍 没有连接SBC时电机行为分析**：
>
> 1. 上电后，`watchdog_enabled_` 初始为 `false`
> 2. `isWatchdogExpired()` 在看门狗未启用时**始终返回false**
> 3. 因此 `move = !false = true`，PID控制循环正常运行
> 4. 但 `target_velocity_` 初始为0，所以PID输出也应为0
> 5. **如果电机在转动**，最可能的原因是：
>    - 编码器读取异常（噪声被PID放大）
>    - PWM初始化瞬态
>    - 硬件问题（DRV8874故障或接线问题）

### 2.3 LED指示灯状态总结

红色LED（PE4）的状态含义：

| 状态 | 含义 |
|------|------|
| 🔴 常亮 | ROS未连接（正常，上电后默认状态） |
| 🔴 闪烁（500ms周期） | 电池电量低 |
| 🔴 SOS闪烁模式 | 系统错误 |
| ⚫ 灭 | 一切正常，ROS已连接 |

### 2.4 LED灯带行为

| 条件 | 灯带表现 |
|------|---------|
| 收到ROS的 `led_strip` 话题消息 | 显示指定颜色 |
| 超过1秒未收到消息 | 进入空闲动画：灰白(0xA0,0xA0,0xA0) ↔ 红色(0xA0,0x00,0x00) 每3.5秒切换 |

## 三、上电后可观察现象时间线

```
时间轴：
  0ms    ┌─ 上电
         │  🔴 红灯亮
         │  🔴 LED灯带亮红色
         │  风扇可能开始转
         │
  ~50ms  │  外设初始化完成
         │
  ~100ms │  ⚡ 电机驱动使能（nSLEEP=HIGH）
         │  ⚡ 可能出现电机短暂抖动（DRV8874唤醒瞬态）
         │
  ~200ms │  串口初始化完成
         │
  ~200ms │  开始2秒通信通道选择窗口
         │  （此时可按按钮1选择诊断模式）
         │
 ~2200ms │  通道选择完成
         │  命名空间协商（最多1秒）
         │
 ~3200ms │  FreeRTOS启动，所有任务开始运行
         │
         │  ┌─ uRosPingTask: 开始ping ROS Agent
         │  │  （每500ms ping一次，超时50ms，尝试4次）
         │  │
         │  │  如果没有SBC连接：
         │  │  → 永远停留在 WAITING 状态
         │  │  → 🔴 红灯常亮
         │  │  → 电机PID运行但target=0（应不动）
         │  │  → LED灯带进入空闲动画
         │  │
         │  │  如果SBC连接并运行micro-ROS Agent：
         │  │  → ping成功 → AGENT_AVAILABLE
         │  │  → 创建ROS实体 → CONNECTED
         │  │  → ⚫ 红灯灭
         │  │  → 可以接收速度指令控制电机
         │  └─
         │
  持续   └─ 各任务周期运行
```

## 四、调试检查清单

### ✅ 正常上电表现（无SBC连接）

- [ ] 红色LED常亮
- [ ] LED灯带亮红色，约4秒后开始灰白/红交替空闲动画
- [ ] 电机可能有极短暂抖动（<100ms），然后静止
- [ ] 风扇低速运转（温度<30°C时约20%占空比）
- [ ] SBC串口（PA9/PA10）无数据传输
- [ ] 诊断串口（PD8/PD9）输出调试信息

### ✅ 正常上电表现（有SBC连接且Agent运行）

- [ ] 红色LED先亮后灭（连接成功后熄灭）
- [ ] LED灯带由SBC控制颜色
- [ ] 电机响应ROS速度指令
- [ ] 串口通信正常（921600bps）

### ❌ 异常情况排查

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| 电机持续转动 | 编码器接线错误/噪声 | 检查编码器A/B相信号 |
| 电机持续转动 | PID积分饱和 | 检查pid_config参数 |
| 电机持续转动 | DRV8874硬件故障 | 检查nFAULT引脚电平 |
| 红灯一直亮 | ROS Agent未运行 | 在SBC上启动micro-ROS Agent |
| 红灯SOS闪烁 | 系统错误 | 连接诊断串口查看错误信息 |
| 灯带不亮 | SPI接线问题 | 检查PC10/PC11/PC12 |
| 风扇不转 | 温度<30°C或接线问题 | 检查PB0输出 |

## 六、关于"电机自检"的结论

**代码中没有编写任何电机自检程序。** 上电后电机的目标速度始终为0，PID控制器应输出0。

如果观察到电机在上电后自行转动，这**不是正常行为**，可能的原因按概率排序：

1. **DRV8874唤醒瞬态**（最常见）：nSLEEP从LOW变HIGH的瞬间，输出端有毛刺，
   导致电机轻微抖动。这是DRV8874的已知特性，通常<100ms即消失。

2. **编码器信号异常**：如果编码器A/B相接线错误或信号质量差，PID可能误判
   电机在运动，从而产生错误的补偿输出，导致电机缓慢漂移。

3. **硬件问题**：DRV8874损坏、IN1/IN2引脚短路、或电源纹波过大。

**建议**：如果电机持续转动超过1秒，请连接诊断串口观察调试输出，
并用示波器检查编码器信号和电机PWM输出。
