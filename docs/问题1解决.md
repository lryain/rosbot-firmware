M1=FL，M2=FR，M3=RL，M4=RR，现在的问题是：
只有m3电机正反转是正常的
m1两个驱动io，复位可以恢复低电平，但是上电后初始化完毕后一直是高电平，似乎是作为其他功能初始化了
m2,m4 的驱动io一直是低电平，没有任何输出

原因：
1. 电机驱动采用的是 DRV8874 的 IN/IN PWM 模式，初始化时会通过 `pinmap_peripheral(pin, PinMap_PWM)` 选择引脚对应的定时器。
2. 对于默认引脚，`pinmap_peripheral()` 会优先返回 PinMap_PWM 里的 PRIMARY 映射，而这些 PRIMARY 定时器刚好和编码器定时器冲突。
3. M1 的 PA6/PA7 默认落到 TIM3/TIM1，M2 的 PB8/PB9 默认落到 TIM4，M4 的 PC8/PC9 默认落到 TIM3；这些都和编码器或其他外设复用，导致实际 PWM 没有按预期输出。
4. M3 的 PE5/PE6 默认映射到 TIM9，没有和其他功能冲突，所以它是正常的。

解决：
1. 给电机驱动增加了可选的 `PinName` 覆盖字段，允许绕过默认 PRIMARY 映射，直接指定 ALT 引脚。
2. 在 `MotorDrv8874::init()` 中优先使用显式指定的 `PinName`，没有指定时才退回到原来的 Arduino 引脚映射。
3. 为 rosbot_lite 的电机配置改用无冲突的 ALT 引脚：
	- M1：PA_6_ALT1 / PA_7_ALT3
	- M2：PB_8_ALT1 / PB_9_ALT1
	- M4：PC_8_ALT1 / PC_9_ALT1
4. 这样可以避开编码器占用的 TIM3/TIM4/TIM1，恢复四个电机的正常 PWM 输出。

验证结果：
- `platformio run -e rosbot_lite` 编译通过。
- 目前软件侧的引脚映射冲突已经修复，后续可再上板确认 M1、M2、M4 的实际波形输出是否正常。
